1. Introducción

Casi todos los programas reciben datos escritos por personas: un correo en un formulario, una fecha de nacimiento, un número de celular o una contraseña. Si esos datos llegan con un formato equivocado, el error aparece después, cuando ya es más difícil de encontrar. Validar a la entrada evita ese problema.

Una expresión regular es una forma corta de describir cómo debe verse un texto. En lugar de revisar carácter por carácter con condiciones, se escribe un patrón como \d{3}, que significa "tres dígitos", y el lenguaje se encarga de compararlo. Con una sola línea se puede decidir si un dato cumple, buscarlo dentro de un texto más largo, reemplazarlo o usarlo para dividir el texto.

Esta práctica desarrolla expresiones para veintiún tipos de datos comunes en Colombia y en programación. Cada una se prueba en Java con la clase Pattern y los métodos de Matcher, usando cadenas válidas e inválidas.

2. Desarrollo

El programa es una aplicación de consola. El usuario escoge un patrón y puede ver su formato, sus ejemplos, la demostración de los métodos o probar un texto propio. Los métodos usados son:

MétodoQué responde
matches()Si todo el texto cumple el patrón.
lookingAt()Si el comienzo del texto cumple el patrón.
find()Cada aparición del patrón dentro del texto y su posición.
replaceAll()El texto con todas las apariciones reemplazadas.
replaceFirst()El texto con la primera aparición reemplazada.
split()Las partes que quedan al cortar el texto donde aparece el patrón.

Las expresiones no llevan ^ ni $: matches() ya exige que cumpla todo el texto, y sin ellos find() puede encontrar el dato dentro de una frase. En su lugar se usan bordes como \b para no tomar un pedazo de otro dato. Las expresiones validan la forma; no comprueban que el dato exista ni calculan dígitos de control.

En cada sección, la tabla separa las cadenas válidas de las inválidas según el resultado de matches(), y el código muestra los seis métodos aplicados a un texto con varias apariciones. Los resultados aparecen como comentarios y se obtuvieron al ejecutar el programa.

3. Conclusiones

Una expresión regular describe la forma de un dato, no su significado. Puede decir que 050012 tiene la forma de un código postal de Medellín, pero no que esa zona exista, ni que un ISBN tenga bien su dígito de control. Para eso hace falta otra validación.

Lo difícil no fue lograr que aceptara los ejemplos correctos, sino que rechazara los incorrectos. \d{2}/\d{2}/\d{4} acepta cualquier fecha bien escrita, pero también 99/99/9999. Para que solo pasaran fechas reales hubo que separar los días según el mes y tener en cuenta los años bisiestos.

Probar con muchos casos mostró errores que a simple vista no aparecían. La contraseña no reconocía la Ñ como mayúscula, y la declaración de variables aceptaba int x = 08;, que Java rechaza. Ambos se corrigieron gracias a las pruebas.

También quedó clara la diferencia entre los métodos. matches() sirve para validar un campo completo, como un formulario, y find() para encontrar datos dentro de un texto más largo. Por eso las expresiones no llevan ^ ni $: así una misma expresión sirve para las dos cosas.

Las expresiones regulares ahorran muchas líneas de condiciones, pero las largas se vuelven difíciles de leer. Armarlas por partes con nombre, como en la declaración de variables, ayudó a entenderlas y a corregirlas sin repetir código.

4. Código fuente

El código completo se entrega en el archivo comprimido junto con este documento. Está organizado así:

src/
├── Main.java                     inicia el programa
├── classes/
│   ├── Patron.java               datos de un patrón
│   └── Evaluador.java            los seis métodos
├── patrones/
│   ├── Catalogo.java             reúne los patrones
│   ├── PatronesColombia.java     placas, postal, teléfonos, barras, normas y precios
│   ├── PatronesFechas.java       fecha y horas
│   ├── PatronesWeb.java          correo, URL y contraseña
│   ├── PatronesProgramacion.java variables, for y double
│   ├── PatronesTexto.java        ISBN, nombres, diptongos e hiatos
│   └── PatronesReferencias.java  IEEE y APA
├── menus/
│   ├── MenuPrincipal.java        lista de patrones
│   └── MenuPatron.java           opciones de un patrón
└── utils/
    └── Entrada.java              lectura y validación

Para agregar un patrón se crea su método en la clase del tema y se incluye en Catalogo; los menús y el evaluador no cambian. Para ejecutarlo se abre el proyecto en IntelliJ con Java 21 y se corre src/Main.java.
